# Personal defaults

- Follow repository instructions and standards. Keep changes focused and preserve unrelated edits and user work.
- Continue authorized work through relevant verification and review. Report what changed, checks run, and remaining limitations plainly.
- Keep workspace-write sandboxing and on-request approvals. Ask me directly before sensitive operations: merges (including local merge to main), branch deletion, destructive commands or issue/PR actions, force pushes or history rewrites, credential access, repository administration, settings or secrets changes, non-GitHub network access, GitHub API access through arbitrary runtimes or shell scripts, and writes outside configured workspace roots.
- Use narrow operation-specific permission prefixes. Never persist broad runtime prefixes such as bash, sh, python, node, ruby, or perl. Request git network approval per command unless the permission mechanism enforces the GitHub remote, active worktree, and non-destructive operation.
